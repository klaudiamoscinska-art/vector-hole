## Architecture

### Config, state, RNG, saves (top of `game.js`)

- **`CONFIG`** is the single tuning object (world, round, hole, growth, eating, economy, difficulty, rival, arena layout, progression, login, chest, hub, evolution, golden, ads, overdrive, campaign, sizeTiers, flags). Old top-level aliases (`WORLD_W`, `BASE_RADIUS`, …) point into it. Tune by editing `CONFIG`, not magic numbers in methods.
- **`CONFIG.flags`** gates major systems; `proceduralDistricts` stays `false` (no authored chunk generator was built).
- **`GameState`** (`BOOT/MENU/MATCH_SETUP/PLAYING/PAUSED/RESULTS`) on `Game.state`.
- **`SeededRNG`** (mulberry32) seeds only a round's *initial* layout (objects, street trails, spawn feasts, spawns) so Daily and friend-challenge maps are identical for everyone; mid-round randomness stays on `Math.random()`. Any new layout step must consume the seeded stream the same way for every player, and `computeDailyLayout()` must replay it exactly (`qa/design.mjs` asserts preview == real round).
- **Save**: `localStorage` key `vectorHoleSave_v1` (never changes), `SAVE_SCHEMA_VERSION` 13 (v22 dropped `energy`, `campaign.discoveredTypes`/`discoveredHoleEating` and every `M00` key) with a `migrateSave()` chain (add an `if (data.schemaVersion < N)` branch per breaking change). Every load runs `sanitizeSave()` against `defaultSave()`, so **a new save field must be added to `defaultSave()`** to survive. `saveGame()` seals the payload (`_sig`). **PX01 save guard:** `loadSave()` never writes on a plain read; a save it can't fully read (`readSave()` → `SAVE_GUARD.state` 'future' / 'corrupt' / 'invalid' (a field `sanitizeSave(save, issues)` had to repair, or `verifyMigration()` failed) / 'unavailable' / 'stale' (another tab wrote)) is played from memory and `saveGame()` — the only write path, cloud mirror included — writes nothing until the player's explicit choice (`releaseSaveGuard()` keeps the original under `SAVE_SLOT + '.rescue'`); a migration commits only after `verifyMigration()` and a copy of the original under `SAVE_SLOT + '.bak'`. Only a save that reached `localStorage` is mirrored to the cloud; an existing empty key is a broken save, not "no save"; a reset of a held-back save aborts if the `.rescue` copy fails. Never write `SAVE_SLOT` around `saveGame()`; `qa/save-safety.mjs` checks it. **PX02 D+ refund:** `save.economy` (`looksOnly` 1 = settled — a new profile is born settled; `migrateSave()` marks a save without the block `looksOnly: 0`, no schema bump) — `settleLooksOnly()` pays the list price of the owned paid vortices (`LOOKS_ONLY_REFUND`, 4870 for the set) once, only on a verified save in `loadSave()` (riding on its migration write, original under `.bak`) or in `adoptSave()` (cloud copy / backup code), and `unsettleLooksOnly()` rolls it back in memory when that `saveGame()` returns false; a paid vortex bought while the line is still unsettled goes to `economy.boughtAfter` and is never refunded; `verifyMigration()` refuses to drop a settled marker; the card (`showLooksOnlyNotice()`) shows once, only after a successful commit (`economy.notice`) and only when its "seen" write succeeds (else it stays pending). `adoptSave()` returns whether the adopted save reached storage (`true` / `false` = memory only / `null` = not adopted); `importBackup()` says „Postęp wczytany” only for `true`. `qa/px02-isolation.mjs` checks it.
- **Ranking is always by score** (`rankHoles()`; radius/name are tiebreakers). Don't reintroduce a radius sort.
- `Analytics` keeps an in-memory buffer and forwards to a host sink only with consent (`save.privacy.analytics`). No backend; the game sends nothing itself.
- `escapeHtml()` for every player-controlled string that reaches `innerHTML`.

### World and rendering

- Fixed 3000×3000 world, `Game.camera` follows the player; Arena zooms out with growth (`Game.zoom` — any screen↔world math must divide/multiply by it; Campaign keeps zoom 1). `render()`/`renderCampaign()` apply one translate for world space; minimap, indicators, goal arrow and juice draw in screen space.
- **`CityFloor`**: 8×8 grid of blocks (`CITY_PITCH` 375, `CITY_ROAD` 64) painted per district into cached chunk canvases (`paintCityChunk()`, `CITY_LOT_PAINTERS`), blitted per frame with lazy repaints, a prefetch ring and an LRU pixel budget. Floor art stays flat, low-alpha, in the district's toned color (`cityTone()`), no shadow blur, no dark disc with a bright rim (that reads as a hole). `qa/visual.mjs` asserts 0 chunk repaints over 60 still frames — keep it that way.
- **Objects** share illustrated sprites (`OBJECT_ART`, cached in `OBJECT_SPRITE_CACHE`, `drawObjectArt()`), identical in Arena and Campaign; `OBJECT_ART_LITE` (gfx level 0) skips per-object sway and live extras. Only draw what `isInView()`.
- **Holes**: `Hole.drawVortex()` spiral arms over a black core, per-skin rims (`SKIN_STYLES`), eaten things drawn inside the vortex while swallowed (`drawSwallowed()`, `swallowGhosts`), leader crown (`isLeader`), labels counter-scaled at far zoom.
- `#app` is `height: 100dvh` (fallback `100vh`): iOS Safari's `100vh` ignores its toolbars and hid the bottom nav labels and the profile reset button. Never size the app with plain `vh`; pad bottom-anchored UI with `env(safe-area-inset-bottom)` (`viewport-fit=cover` is on). Home-screen app: the status bar style is `black` on purpose — with `black-translucent` WebKit on notched iPhones reports the viewport minus the status bar while drawing from the screen top (black strip, clipped minimap); stretching `#app` past it doesn't work because html/body clip it. `resize()` measures `#app`, and every `.screen` pads `env(safe-area-inset-top)`.
- **Big screens (v21):** `resize()` sets `Game.viewScale` = clamp(√(screen area / `CONFIG.juice.zoom.viewArea`), 1, `viewScaleMax`) — multiplied into Arena's zoom and used as Campaign's zoom (`renderCampaign()` scales; darkness, goal arrow and camera clamp use `this.zoom`), so a laptop sees about a phone's worth of city with a big vortex; phones stay at 1. **Landscape layout (FTUE-2):** `resize()` asks `screenLayout(w, h)` — `'phone'` (w < 560 or w < 1.25·h), `'wide'` or `'compact'` (wide but h < 620: a phone on its side, Poki 640×360/836×470/1031×580, CrazyGames 800×450) — and sets `body.wide` (+ `body.compact`) and `Game.layout`; `uiScale` = clamp(min(H/620, W/1100), 1, 1.6) on wide, exactly 1 on compact (it never goes below 1: text stays ≥ 9 px at DPR 1). Compact rules are the `body.compact` block at the end of `style.css` (narrower rail, two columns at scale 1, overlays scroll inside with the main action in view, HUD: standings = leader + you, `minimapSize()` 92, NELA/hints at the edges, smaller/higher banner); the bottom nav becomes a left rail and every hub screen two columns — Miasto by grid placement, the others through `.wide-col.wide-col-a/-b` wrappers in `index.html` that are `display: contents` on a phone (Dzielnice keeps its phone order with CSS `order`; never use `>` child selectors to reach elements inside a wrapper). Dzielnice shows all 12 districts as a grid there. Otherwise `Game.uiScale` (1 on phones, up to 1.6) drives `--ui-scale`: `#app > :not(#gameCanvas) { zoom }` grows every menu/sheet/HUD layer, `prepCanvas()` renders UI canvases that much sharper, `minimapSize()/minimapMargin()` scale the canvas minimap. Never read DOM rects to position elements inside a zoomed layer. The district strip scrolls with a mouse wheel and fades where cut off (`bindDistrictStrip()`, `updateStripEdges()`). `qa/v21.mjs` checks phones unchanged + desktops.
- Adaptive quality: `GFX_LEVELS`, `Game.applyGfx()`, `monitorFrame()` steps down on slow devices.
- In-round HUD writes go through `Game.hudSet()` (DOM write only on change). Juice helpers: `FloatText`, `flashScreen()`, `showBanner(text, sub, color, duration, priority)` (one banner at a time), `addScorePop()`, `hitStop()`, `spawnSuck()`. Use SVG/canvas glyphs, not emoji.

### Input

FTUE-2 (portal iframes): the vortex stops when the mouse leaves the document (`mouseleave`, mouse only) and on window `blur` (held keys released, thumb pad reset, a live round pauses unless an ad is running); Escape / P / Space pause (Space keeps clicking a focused menu button); keys typed in a text field never steer; a `wheel` / scroll-key guard (`canScrollToward()`) lets the game's own panels scroll and stops everything else so the portal page never scrolls (Ctrl+wheel zoom too); the consent bar reserves its height (`reserveConsentSpace()`, `body.consent-open`, `--consent-h` = its rect / `uiScale`). `qa/responsive.mjs` checks all of it. FTUE-2 FIX (real devices): `resize()` also runs from a `ResizeObserver` on `#app` and after `orientationchange` (an iPhone home-screen app's resize came before the box settled), keeps the canvas bitmap when the size is unchanged, and measures the safe-area insets (`game.safe`, a hidden `#safeAreaProbe`); `followCamera()` lets the city's edge stop at the safe area; the minimap (`minimapRect()`), edge arrows (`edgeMarkerPos()`) and banners keep clear of insets and HUD; `fadeHudUnderHole()` / `hudFade()` dim a HUD panel the vortex is under (boxes from `offset*` × `uiScale`, no DOM rects in a zoomed layer); `setBoardLive()` clears and hides the board outside a round (`body.board-idle`) so a menu fading in never shows the last round's frame; `splitMissionCard()` puts the briefing / start card's text in its own scroll box above GRAJ / START. `qa/devices.mjs` checks these.
`save.settings.inputMode` (default `'legacy'` = direct drag; `'thumbpad'` = floating joystick in the bottom 35 %, gated by `CONFIG.flags.inputThumbPad`). Direct drag keeps the finger/cursor **screen** position (`pointerScreen`) and re-projects it through the camera every frame in `applyPlayerMovement()`; `pointerScreen` is cleared at round/mission start and on touch end, so the hole never drives itself and a held finger keeps steering. WASD/arrows are checked first.

### Arena round

- `startRound()` → `createObjects()` (seeded `TIERS` pool + `layStreetTrails()`), `createEntities()` (`rollSpawns()`, bots tuned by `Game.botTuning` from `difficultyT`, then `layStarterFeasts()`), pacer setup, 2.5 s spawn shield. `update()` → movement, bots, eating (`handleObjectEating()`, `holeCanEat()` = size-tier gate only; `lockedBump()` explains a too-big object), hole collisions (`EAT_HOLE_RATIO` 1.15, area-conserving growth), `updatePacer()`, tiers, evolution, overdrive, combo, HUD.
- **`TIERS` mirrors Campaign's bestiary 1:1** (fragment/capsule/prop/marker/vehicle/node/pylon/landmark/structure/heavy/tower — same colors, sizes, tier gates as `CAMPAIGN_ENTITY_STATS`). v22: Arena spawns its whole bestiary from the first round — nothing in Arena depends on campaign progress (and nothing in a mission on Arena progress); keep it that way.
- Growth: every eat adds `growth` units on the shared piecewise-linear curve (`CONFIG.growth`, `growUnits()`/`radiusForUnits()`); radius only via `setRadius()`/`growUnits()` (enforces `CONFIG.hole.maxRadius`).
- **Pacer rival (`CONFIG.rival`)**: `Game.pacer` (bot 0) follows a par curve from `save.stats.recentArenaScores` (last 5 finished rounds) and tails a runaway player; `paceMult` scales its points/growth, `paceHungry` widens its food range. Lead-change and final-chase banners live in `updateHUD()`.
- Difficulty: `computeDifficultyT()` from runs played (Daily/challenge use fixed `dailyT`); no Rush Hour at t = 0.
- Evolution cards (`MUTATIONS`, `offerEvolution()`, `showPowerCards()`) fully pause the round; POMIŃ skips; `autoPickMs` is only an AFK safety net. FTUE-3: none in the first regular Arena round (`startRound()` sets `evolutionQuiet` while `arenaRunsOf(save) < CONFIG.ftue.evolutionFromRuns` and the round is not a Daily or a challenge; `checkEvolutionTriggers()` returns early) -- the first offer of the next round says „NOWOŚĆ · EWOLUCJA” (`evolutionIntro`, `showPowerCards(…, kicker)` → `#evolutionKicker`; campaign powers keep „EWOLUCJA”).
- **Edge reach (FTUE-3, `edgeReach()`, `CONFIG.arena.edgeReachSlack`)**: a hole's centre is clamped a radius from the world edge, so the player's vortex pressed against a wall also takes objects (`handleObjectEating()`) and smaller rivals (`handleHoleCollisions()`, ratio rule unchanged) lying in the strip it can't enter -- only when its centre is within `edgeReachSlack`·r of the closest reachable point. Player only; bots are unchanged. Overdrive ("WIELKI FINISZ", `checkOverdriveTrigger()`), Złoty Rdzeń + SZAŁ (`CONFIG.golden`).
- `endRound()` → `finalizeRun()` (coins, XP, Core City, Daily, stats, recent scores) → results screen with a sticky action bar. `leaveRun()` (pause → OPUŚĆ RUNDĘ) never runs `finalizeRun()` (R1, owner decision): with a score it goes through `payLeftRun()` — only the score part of the coin/XP formulas (`coinsSqrtK`·√score × newbie multiplier, `xpSqrtK`·√score), no Core City, place bonus, prism trickle, daily mission, Daily bonus/record/streak, PB, recent scores or `runsPlayed`; at score 0 through `abandonRun()` — nothing at all. `runsPlayed` therefore counts finished rounds (older saves keep their count) — `qa/leave-run.mjs`.
- **No Arena advantage for sale (PX02 D+, owner decision):** vortices are looks only (no `perks`, no `Game.perk()`), there is no run-tool screen (`RUN_TOOLS`, `confirmRunSetup()`), result upsell or `turbo_free` ad — GRAJ / replay / the friend rematch start the round at once (`startArenaRound()` = `startRound()`). Never reintroduce anything coins, prisms, ads, IAP or campaign progress buy that changes an Arena round (start size, speed, magnet, shield, points, growth, combo, coins/XP for a result). The one accepted flow between the modes is deliberate: Arena-earned coins may buy a mission booster in the briefing.

### Campaign

Separate simulation (`Game.mode` 'campaign', `updateCampaign()`/`renderCampaign()`, `CampaignEntity` list). Missions are authored as `MISSION_SPECS` objective lists (Rozdział I) and compact `CHAPTER_II` rows (`[name, 'e:TYPE:N b:N t:K c:N g:N r:N a:node:N L:id s:N', 'H2 R D Z2 F O W B50', diff]`, parsed by `chapterTwoSpecs()`, ids M61+), all compiled by `compileMission()`. Each mission has `diff` 1–5 (`DIFFICULTY`): time limit = `MISSION_BOT_TIME[id]` median × timeFactor + pad, spares shrink with diff, `stars` = [clear, fast time, expert time or the spec's special `medal`] — **when adding or changing a mission, add a spec/row, re-run `node qa/calibrate.mjs 10 4`, paste `MISSION_BOT_TIME`, then `node qa/difficulty.mjs`.** v15 twists (setup flags): `hunters` (first N bots chase in bursts, `updateCampaignBot()`), `racer` (`this.racer`, `updateRacerBot()`/`resolveRacerEat()`, starts once the hole can eat the race type), `dark` (`drawDarkness()`, `darkVision()`), `glitch` (`this.glitchZones`, `updateGlitchZones()`), `fragile`, runner goals (`updateRunners()`). Every hazard goes through `campaignHit()` (shield → fragile fail → growth loss); early losses through `failCampaignMission(reason)` (`m.failReason` 'time'/'racer'/'hit'). Every mission starts via the briefing (`launchMission()`: boosters from stock then coins), then waits on the tap-to-start card (`showMissionStartCard()`/`beginMissionPlay()`, `introPending`; QA bots call `beginMissionPlay()` to clear it). There is no tutorial mission (v22 removed `M00`; the campaign starts at M01, where NELA introduces herself; mission codes are unchanged). `drawCampaignGoalArrow()`/`campaignGuideTargets()` point to off-screen goal objects. **Gates are helpers, never goals (v20):** `setup.gates` (row token `g:N`) lays impulse pads on the roads (`layImpulsePads()`, `useImpulsePad()`: +50% speed for 2.5 s via `Hole.impulseMult`, then a 5 s recharge), `gateKind: 'portal'` (row twist `O`) a linked two-way pair (`usePortal()`); both get a briefing chip (`TWIST_INFO.impulse/portal`). Mostek has its own mechanic (`handleCampaignBridges()`). Mission end: `endCampaignMission()` → stars (`missionStarBits()`, `save.campaign.stars` bitmask, `checkStarChests()`), fail streak / NELA's pity Zegar → `missionResultScreen` (stars, fail title, NELA bubble, and the next mission's card above „GRAJ Mxx”, which opens its briefing); revive (ad or `CONFIG.ads.revivePrisms`) via `onCampaignTimeout()`. **Every mission is briefed before it starts** with one shared card, `missionCardHtml()` (goals from `missionStepRows()`/`objectiveIconDef()`, time, medal, reward, optional `[data-mc-play]` GRAJ handled by one delegated click listener): the briefing sheet (`openMissionBriefing()`, on any mission tap and the hub's campaign tile), Dzielnice's "NASTĘPNA MISJA" card and the result preview. `nextCampaignMissionId()` = first uncleared playable mission across unlocked districts. NELA is a character: `NELA_AVATAR` SVG in every `.nela-avatar`, `.nela-bubble` speech bubbles, `showNelaToast()` + `SoundEngine.nela()`, district stories in `DISTRICT_STORY`. **Campaign never touches Core City** — only `finalizeRun()` (Arena/Daily) does. **CONTENT-1:** a goal row's icon comes from `objectiveIconDef()` → `goalArtKind(type, glyph)` → `CampaignEntity.artKind()` (the look the board draws) → `GOAL_ART_ICONS[art]`; a step naming no glyph whose type is laid in random looks (`CAMPAIGN_RANDOM_LOOKS`: props, structures, heavies, towers without the kopuła) gets the class icon `GOAL_ICONS[type]`. A new object look needs an `OBJECT_ART` sprite, a `GOAL_ART_ICONS` entry and a `NOUNS` entry — `node qa/content.mjs` fails on a shared or missing icon. Pylon spots are reserved in `taken` before the food. The campaign camera is `campaignTargetZoom()` (lerped in `updateCampaign()`, set on resize): `viewScale` until the hole passes `CONFIG.juice.zoom.holeScreenFrac` of the short side, then pulled back, floored at the short side showing the whole mission box — visual only.

### Dev / QA panel (v23)

`DevPanel` (just before `I18N_EN` in `game.js`) + `.dev-*` CSS: an owner-only test panel. Access: 7 quick taps on Profil's guest ID line (or `?dev`) → dev code; only `DEV_CODE_HASH` (salted SHA-256 × `DEV_CODE_ROUNDS`, `devCodeHash()`) is in the source — **never commit the code itself**; change it with `node qa/dev-code.mjs "<code>"`. Loopback hosts also accept `DEV_LOCAL_CODE` (`dev`) for QA. `devBoot()` (before `new Game()`) reads the access token and **test mode**: `SAVE_SLOT` = `DEV_SANDBOX_SAVE_KEY`, so `loadSave()`/`saveGame()` never touch the real save; `DEV.sandbox` also cuts the cloud mirror, the analytics sink, real ads/IAP and portal gameplay markers. Every panel action requires test mode and goes through the game's own methods; lists come from the game's data tables, so new missions/cosmetics/boosters/products appear automatically. Hooks in game code (`isMissionPlayable()` via `DEV.openMissions`) must stay inert outside test mode. Panel UI is Polish-only (`translate="no"`). Extend `qa/dev-panel.mjs` with new panel actions.

- **Saves (v19)**: `saveGame()` stamps `meta.savedAt` (not on a plain load) and mirrors to `SAVE_MIRROR` — set by `Monetization.attachCloudSave()` on CrazyGames (its data module syncs logged-in players across devices); on attach the save with the higher `saveProgressScore()` wins (never a fresh device over a long campaign), and `Game.adoptSave()` swaps it in (deferred until no round runs). Profil → Kopia zapasowa: `encodeSaveCode()`/`decodeSaveCode()` (`VH1.` + base64 of the sealed save). `navigator.storage.persist()` is requested at boot (not on Firefox, which would prompt).
- `Monetization` is the only path to ads/IAP (`rewarded()`, `interstitial()`, `purchase()`); providers are detected at runtime, the web build runs a labelled demo and never shows a fake checkout. `SoundEngine` synthesizes all audio (never audio files). **Music (v16)**: `MUSIC_TRACKS` is a data bank of 15 tracks (3 `menu`, one theme per district; lead = note tokens, bars of exactly 16 steps — `qa/audio.mjs` checks), compiled lazily by `compileSong()`; the sequencer (`scheduleUntil()`/`advance()`/`playStep()`) walks each track's `form` of sections, layers by `intensity` (0 outro/menu · 1 round · 2 final stretch → riser + jump to the `drop` section · 3 SZAŁ; in the final stretch a wrap loops hook → drop instead of rotating). The game only calls `setScene('menu' | 'arena' {seed, daily, challenge} | 'campaign' {district, boss})` — results screens keep the round's track — plus `setIntensity()`; `playTrack()` fades and switches on a downbeat, Arena/menus rotate after each full pass, missions loop their district theme, `missionStart()` drops a boss theme on START. UI reads `currentSong` (the queued track during a fade). Track maps are prototype-free (`Object.create(null)`). Rozdział II themes unlock with their district (`isTrackUnlocked()`); `save.settings.musicPick` pins a favourite (Szafa grająca in Profil, `openJukebox()`); the pause sheet's NASTĘPNY calls `skipTrack()`; `onTrackChange` drives the „TERAZ GRA” chip. Pitched SFX follow the track's key (`song.ladder`, `inKey()`). Add a track = one `MUSIC_TRACKS` entry, then `node qa/audio.mjs`. iOS rules (v13.2): `unlock()` runs on every pointerup/touchend/click (pointerdown is not a user activation in Safari), sets `navigator.audioSession.type = 'playback'` (else the silent switch mutes Web Audio), resumes from any non-running state (WebKit uses `interrupted`), on iOS also starts a silent looping in-memory WAV `<audio>` (`unmuteIOS()` — WKWebView/Chrome iOS and older iOS have no `audioSession`, and without media playback the ring/silent switch mutes Web Audio while the context still says `running`), rebuilds a context that won't resume, and respects `hold` (set by `suspend()` for ads / hidden page, cleared by `resume()`). `qa/features.mjs` simulates these states.

## Languages (v19)

Polish is the source language; English is a translation layer at the output (`I18N`, `T()`, `i18nStart()` near the top of `game.js`, dictionary `I18N_EN` at the bottom): a `MutationObserver` translates DOM text and `aria-label`/`placeholder`/`title`, and `fillText`/`strokeText`/`measureText` are wrapped for canvas text. Keys are the Polish strings; composed text uses patterns — `{0}` any text (translated recursively), `{#0}` a number only (use it for "number + noun" so names aren't hijacked). UPPERCASE variants are automatic. `save.settings.lang` ('auto' = the browser: Polish for `pl-*`, else English; Profil switches and reloads). **Every new Polish UI string needs an `I18N_EN` entry** — run `node qa/v19.mjs` (it fails on any Polish reaching the screen in English) and, for a manual pass, open the game with `?i18n=all`. Text inside `[translate="no"]` is left alone (backup code, language buttons). QA suites run as `pl-PL` by default (`openGame(..., { locale })`).

## Runtime files and `design/` (from the old CLAUDE.md Project section)

Vanilla HTML/CSS/JS, zero dependencies, no bundler and no build step for development. Since E2 the game runs from native ES modules (owner decision 2026-10-18: several JS files are allowed, no bundler, no dependencies, no gameplay change while refactoring; the old "exactly three runtime files" rule is lifted). Today's runtime sources:

- `index.html` — canvas, in-round HUD, and every screen (Miasto hub, Dzielnice, mission briefing sheet, Warsztat, Wyzwania, run setup, profile, pause, quick-equip, evolution cards, game over, ad, mission result) present in the DOM at once and toggled with `.hidden`, plus a persistent bottom nav.
- `style.css` — neon visual system, responsive layout (phone first, desktop too), self-hosted subsetted fonts as base64 `@font-face` (the default build makes **zero** third-party requests — keep it that way).
- `game.js` — all game logic in one long file, loaded as a native ES module since E2 (`<script type="module" src="game.js">`; its top-level names aren't globals — the `export { … }` at the end lists only what `qa/` reads through the QA bridge, see `qa/README.md` E2) (ES6 classes: `Game`, `Hole`, `Bot`, `WorldObject`, `CampaignEntity`, `CityFloor`, `SoundEngine`, `Monetization`, `Analytics`, `SeededRNG`, `Particle`, `FloatText`, `Ripple`).

**Splitting `game.js` into ES modules is an approved, staged refactor (E2 → E3 → E4): one step at a time, no gameplay change, static relative imports only (`./`, inside the release; no bare, absolute or dynamic imports — the release script rejects them). Adding a dependency, a bundler, or a build step that development depends on still needs the owner's decision first** — the zero-dependency rule stands. The CI release assembly (Deployment) is not a development build step.

`design/` holds the original authored mockups (non-runtime): `reference/asset_bible.svg` is the palette source of truth; `screens/*.svg`, `assets/` and `gameplay/` (with their `.md` specs) are the original layouts and the v6 object/landmark specs — the game has evolved past the screen layouts since.
