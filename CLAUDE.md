# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Vector Hole: Eat the Neon City** — a top-down, hole.io-style browser game, built out as the "Golden Shot V2" hybrid-casual product per `docs/VECTRE_V2_PLAN.md`, extended with a mission-driven **Campaign mode** ("Vector Hole v3") per `docs/VECTRE_V3_PLAN.md`, given its final meta-progression economy and full 24-mission campaign ("Vector Hole v4") per `docs/VECTRE_V4_PLAN.md` and the source GDD at `docs/VECTOR_HOLE_GDD_4_0.pdf`, then brought pixel-close to a set of authored screen mockups in a UI/visual-parity pass ("Vector Hole v5") per `docs/VECTRE_V5_PLAN.md`, then given per-mission object sprites, unique landmark silhouettes, and real mechanics for Portal/Mostek/Pas przelotu in a Campaign mission-object enrichment pass ("Vector Hole v6") per `docs/VECTRE_V6_PLAN.md` then given a retention/balance/juice „Golden Shot” pass (XP levels, 7-day login calendar, free chest, career difficulty curve, camera zoom, float texts/banners/confetti) ("Vector Hole v8") per `docs/VECTRE_V8_PLAN.md` (all six are full audit + roadmap + changelog docs — read the relevant one before making architectural changes). Vanilla HTML/CSS/JS with zero dependencies and no build step, deliberately kept to exactly three files:

- `index.html` — canvas element, in-game HUD overlays, and every screen (Miasto/Core City hub, Dzielnice/campaign map, Warsztat/shop, Wyzwania, run setup, profile, pause sheet, quick-equip popup, evolution cards, game-over, ad, mission result) all present in the DOM at once, toggled via the `.hidden` class, plus a persistent bottom nav bar.
- `style.css` — cyberpunk neon visual system (palette lifted from `design/reference/asset_bible.svg`), responsive layout (desktop + touch/mobile), CSS animations for pulsing neon glows.
- `game.js` — all game logic, in one (long) file, using ES6 classes: `Game`, `Hole`, `Bot extends Hole`, `WorldObject`, `CampaignEntity`, `Particle`, `Ripple`, `SeededRNG`, `Analytics`.

`design/screens/*.svg` and `design/reference/asset_bible.svg` are the authored reference mockups for the v5 pass — non-executable design assets (not part of the "three files" runtime), kept in the repo as the visual source of truth for the Miasto/Dzielnice/Warsztat/Wyzwania/Pauza/Wynik-rundy/Wybór-narzędzia screens and the in-round Arena object bestiary. When touching any of those screens, compare against the matching SVG before inventing a new layout. `design/assets/vector_hole_full_object_catalog.svg` and `design/gameplay/vector_hole_mission_board_finale.svg` are the equivalent visual source of truth for the v6 pass — the Campaign mission-object catalog and the 6 landmark silhouettes, respectively, each paired with a companion `.md` spec in the same folder.

This project went through Golden Shot V2 Phases 1–9 in one pass (see `docs/VECTRE_V2_PLAN.md` §4–§9 for the exact scope and honest gaps of each), Campaign mode in a second pass (`docs/VECTRE_V3_PLAN.md`), the v4 meta-economy/full-campaign/navigation pass (`docs/VECTRE_V4_PLAN.md`), and the v5 UI/visual-parity pass (`docs/VECTRE_V5_PLAN.md`) — a palette/layout pass matching the screens above, not a new game system. The file is now large; **do not split it into multiple files or introduce a build step without first flagging that decision to the user** — the "exactly three files, zero dependencies" constraint is a deliberate, repeated instruction, not an oversight.

## Commands

There is no package manager, build step, linter, or test suite. To run the game locally, serve the directory with any static file server and open `index.html`, e.g.:

```bash
python3 -m http.server 8000
# then open http://localhost:8000/index.html
```

Opening `index.html` directly via `file://` also works. There is no automated test suite; verification has been done via manual play-throughs and ad-hoc Playwright scripts against a local static server (see recent commit messages for what was checked each phase) — write similar throwaway scripts rather than assuming a `tests/` directory exists.

## Deployment

Pushing to `main` triggers `.github/workflows/deploy-pages.yml`, which deploys the repo root as-is to GitHub Pages (no build step — it just uploads `index.html`/`style.css`/`game.js`). The workflow also runs on `claude/**` branches, but the `github-pages` environment's branch protection only allows deploys to actually go live from `main` — pushing the workflow file to a feature branch will run it, but the deploy step will fail with an environment-protection rejection until the branch is merged. `.nojekyll` is present at the repo root to stop GitHub Pages from running its default Jekyll processing on the static files.

## Architecture

### Config, flags, state machine, RNG, analytics (all in `game.js`, top of file)

- **`CONFIG`** is the single data-driven tuning object — world/round/hole/eating/economy/input/juice/evolution/overdrive values all live here, with old top-level `const` names (`WORLD_W`, `BASE_RADIUS`, etc.) kept as one-time aliases into it so the rest of the file didn't need touching when it was introduced. Tune gameplay by editing `CONFIG`, not by hunting for magic numbers in methods.
- **`CONFIG.flags`** gates every major system (`inputThumbPad`, `evolutionSystem`, `runModifiers`, `hub`, `shopV2`, `dailyChallenge`, `monetizationAdapters`, `analyticsConsoleLog`, `proceduralDistricts`). Most are now `true` (the systems are built); `proceduralDistricts` and `monetizationAdapters` stay `false` because a full authored chunk/district generator and real ad/IAP SDKs were explicitly **not** built (see plan doc — no backend, no secrets, no store credentials belong in this repo).
- **`GameState`** enum (`BOOT/MENU/MATCH_SETUP/PLAYING/PAUSED/RESULTS`) is tracked on `Game.state` and updated at the same call sites that already drove screen changes.
- **`SeededRNG`** (mulberry32) backs `Game.rng`, created fresh per round from `Game.runSeed`. It seeds the *initial* world layout only (see `seededRand()`'s doc comment) — mid-round randomness (bot wandering, object respawn after being eaten, particles) intentionally stays on `Math.random()`. The Daily Seed Challenge (`dailySeedForDate()`) derives a deterministic seed from the UTC calendar date.
- **`Analytics`** is a console-log stub (`Game.analytics.track(name, props)`) with an in-memory ring buffer. Wired at most of the GDD's minimum event list; a few events tied to systems that still don't exist (backend accounts, IAP) are documented as not-fired rather than faked.
- **Save schema** is versioned (`SAVE_SCHEMA_VERSION`, currently 10) with a `migrateSave()` chain — add a new `if (data.schemaVersion < N)` branch per future change rather than replacing the function. The `localStorage` key itself (`vectorHoleSave_v1`) never changes.
- **Ranking is always by score**, with radius/name as documented tiebreakers, via the shared `rankHoles()` helper — used by the live HUD rank badge, Arena's `finalizeRun()`/results screen, and nowhere else needs its own sort. Don't reintroduce a radius-based sort for "who's winning" (see `docs/VECTRE_V3_PLAN.md` §2 for the bug this fixed).

### World and coordinate spaces

The game world is a fixed 3000×3000px plane (`WORLD_W`/`WORLD_H`), independent of screen size. `Game` owns a `camera` (`{x, y}`) that follows the player, clamped to world bounds. `Game.render()` applies one `ctx.translate` for world-space drawing (grid, `WorldObject`s, `Particle`s/`Ripple`s, `Hole`s, the can-eat rim, danger halos, bounty/scanner markers); `drawMinimap()` and `drawDangerIndicators()` reset the transform to draw in screen space afterward. The minimap is visible by default on every viewport — an earlier pass auto-hid it below 700px width, which was effectively every phone, read as "the minimap is missing," and was reverted; only `settings.minimap === 'off'` hides it now.

### Input

Two control schemes, chosen by `save.settings.inputMode` and gated by the `CONFIG.flags.inputThumbPad` kill switch:
- **Floating Thumb Pad** (default): touch-down inside the bottom `CONFIG.input.zoneHeightFraction` of the screen anchors a translucent joystick wherever the thumb lands (dead zone, max radius, a curved response). Drives `Game.moveVector` → `Hole.moveDirection()`.
- **Legacy direct-drag**: the hole chases `pointerWorld` via `Hole.moveToward()` — unchanged since before Golden Shot V2, still the only mode on desktop mouse. WASD/arrow keys are an accessibility option, checked first in `Game.applyPlayerMovement()`.

### Entities

- `Hole` is the shared base for player and bots: position, `radius`, `score`, skin/aura, invulnerability window, `moveToward()`/`moveDirection()`/`growFromArea()`/`shrinkAndRespawn(bonusInvulnMs)`. `getSpeed()` multiplies by `this.tempSpeedMult` (set per-frame for the Slipstream mutation, set once at round start for the Rush Hour modifier). Object eats grow a hole along one shared piecewise-linear curve, `CONFIG.growth` (`growUnits()` → `radiusForUnits()`/`unitsForRadius()`): each eaten type adds its GDD `growth` units (fragment 1, prop 3, vehicle 6, …) and the radius is read off the curve, so early pickups are a visible ~2 px each and the radius at every tier threshold is exact. Every T2+ object's size sits between the previous anchor and its own unlock anchor, so it looks too big before unlock and visibly smaller than the hole once eatable; highlight/goal rings add only a few px. Hole-vs-hole eats still use area-conserving `growFromArea()`. Campaign's radius is a pure function of `mission.growthUnits` (`syncCampaignRadius()`). Any radius increase triggers a short draw-only "gulp" pop (`setRadius()`).
- `Bot extends Hole` adds a `decide()` state machine (flee/hunt-hole/hunt-obj/wander), no pathfinding.
- `WorldObject` instances are pooled; `respawn(tierName, first, rng)` only uses `rng` when `first` is true (the run's initial deterministic layout). **`TIERS` mirrors Campaign's `CampaignEntity` bestiary 1:1** (player feedback: the two modes should use exactly the same objects, Campaign being the reference for every property) — each `TIERS` key is one of Campaign's own types (`fragment`/`capsule`/`prop`/`marker`/`vehicle`/`node`/`pylon`/`landmark`), with color/radius/value/`minSizeTier` taken straight from Campaign's `SIZE_TIER_COLORS`/`CONFIG.campaign.entityRadius`/`CAMPAIGN_ENTITY_STATS`, so a fragment, a lamppost, or a landmark is the same object (same color, same size, same growth-tier gate) in both modes; `subtypes` still gives multi-glyph types (`prop`) visual variety, matching Campaign's own `PROP_STREET_GLYPHS`. `landmark` reuses Campaign's generic double-ring fallback shape (Arena has no per-mission silhouette identity or locked/unlocked state) rather than the old Arena-only `skyscraper`/`fontanna` pickups, which were removed since Campaign has no equivalent for either. `portal` stays a separate entry outside this shared bestiary (Campaign has no pickup like it at all) — the bible's violet functional-accent glyph, used only for `spawnPortalRain()`'s Overdrive bonus wave, never a normal spawn — but it's still tier-gated (`minSizeTier: 3`, same as `landmark`) rather than exempt from the growth gate; an earlier "deliberately ungated" version let a player eat it at any size, which read as a bug once Arena and Campaign were expected to be exactly the same gameplay.
- **Object art (`OBJECT_ART`, `drawObjectArt()`)**: every common pickup (fragment, kapsuła, latarnia/drzewo/ławka/kiosk/skrzynia, znacznik, samochód, węzeł, pylon, Arena's generic landmark, portal) is an illustrated, gradient-filled sprite in shades of its tier color, painted once per kind/color/radius into `OBJECT_SPRITE_CACHE` (offscreen canvas) and blitted per frame, with cheap live extras (bob/breathe, fragment twinkle, spinning reactor arcs, pylon pulse, portal swirl) from `drawObjectLive()`. `WorldObject.draw()` and `CampaignEntity.draw()` (via `artKind()`) share it, so an object looks identical in both modes; Campaign's mission-specific glyphs (paleta, kryształ, mostek, lustro, landmark silhouettes, …) keep their bespoke line art over the same tier-colored ground glow. Both renderers skip anything outside the camera view (`Game.isInView()`).
- **Hole vortex (`Hole.drawVortex()`)**: every hole has four spinning spiral arms (`drawSpiralArms()`) in light/base/dark shades of its skin color (rainbow hues for Tęcza/Pryzmat) over a black event-horizon core. The Warsztat live preview and the Rdzeń/Trail grid swatches are drawn by the same `Hole.draw()` (`Game.drawHoleThumb()`, animated by `startWarsztatAnim()` while the shop is open), so the shop shows exactly what plays.
- Eating rules: `Game.handleObjectEating()` / `handleHoleCollisions()`, gated by `canEatWorldObjectTier()` for world objects and `EAT_HOLE_RATIO` for hole-vs-hole — a hole must have grown to a `TIERS` entry's `minSizeTier` (an index into `CONFIG.sizeTiers`, Arena's own T1-T5 growth ladder) before that object type is eatable at all, the same way Campaign gates `CampaignEntity` types by `campaignPlayerTier()`/`e.stats.minTier` in `handleCampaignEating()`. World-object eating has **no physical size-ratio requirement** (an old `EAT_OBJ_RATIO`, "object must be under 90% of the hole's radius", was removed — Campaign never had one, and keeping it forced Arena's tier thresholds above Campaign's own growth-unit pacing to avoid a tier badge flipping before its objects were actually small enough to pass the ratio check); the tier gate alone is what's checked everywhere eat-eligibility matters (`handleObjectEating()`, `Bot.decide()`'s hunt-obj targeting, the Magnet Pulse mutation's pull radius, `canEatHighlight()`'s breathing-rim glow, now a flat 0/1 rather than a fading "getting close" value since there's no ratio left to fade over), not just at the point of consumption. `CONFIG.sizeTiers[].minRadius` is filled from `CONFIG.growth.radiusAnchors`, and `CAMPAIGN_TIERS[].minUnits` equal `CONFIG.growth.unitAnchors` (6/22/50/100/180), so crossing a given tier takes the same pickups in both modes. Tier colors are cyan/pink/gold/violet (T3 moved from green to gold because green and cyan blurred together on the minimap); on both minimaps objects are squares and holes are rings (white player dot, red ring = bigger rival, white ring = smaller). Both eat sites route through `Game.triggerEatFeedback()` (size-scaled particles/shake/ripple) and `Game.registerCombo()` (score multiplier + fading combo text).

### Game loop, pause, and screens

`Game.loop()` drives one `requestAnimationFrame` chain, gated by `this.running`; `update()`/`updateCampaign()` are skipped entirely (a true pause, not a scaled-down `dt`) while an evolution/power card offer is pending, so the round is frozen — position, timers, everything — until the player picks a card or dismisses the overlay. `pauseGame()`/`resumeGame()` cancel/restart the RAF loop rather than adding a "paused but still ticking" branch. Screens are plain DOM show/hide via `showScreen()`/`hideAllOverlays()` — still no router or framework, just more screens now (`runSetupScreen`, `profileScreen`, the pause sheet, evolution card overlay, overdrive banner). The pause sheet, leave-run confirm, and quick-equip popup (below) are `.overlay-screen`s: a translucent scrim over the frozen last-drawn canvas frame (RAF is already cancelled, so the frame just sits there) instead of `.screen`'s opaque full-screen background, matching `design/screens/pauza.svg`/`wybor_narzedzia.svg`.

### Golden Shot v8: retention, difficulty curve, juice

See `docs/VECTRE_V8_PLAN.md`. `CONFIG.progression`/`loginRewards`/`freeChest` drive the XP level (`Game.grantXp()`), the 7-day login calendar and the 4 h free chest (`save.player`/`save.login`/`save.freeChest`). `CONFIG.difficulty` maps the player's Arena run count to `Game.difficultyT` → `Game.botTuning` (bot size/speed/aggression), so early runs are easy wins and later runs push toward run tools (Turbo start). Arena's camera zooms with growth (`Game.zoom`; any new screen↔world math must divide/multiply by it — Campaign keeps zoom 1). `FloatText`, `flashScreen()`, `showBanner()`, `hitStop()` are the shared juice helpers for both modes.

### Evolution + Overdrive ("Golden Shot")

Two evolution offers per run trigger at `CONFIG.evolution.triggerRadii` (player radius crossings). `Game.offerEvolution()` shows up to 3 weighted-random cards from the `MUTATIONS` pool above the Thumb Pad zone (Campaign's `offerCampaignPowers()` reuses the same overlay for `CAMPAIGN_POWERS`); the player can pick a card or hit the "POMIŃ" button (`skipEvolutionOffer()`) to close the offer without picking anything, and `autoPickMs` auto-picks the first option only as an AFK-tab safety net so a round can never soft-lock. Picked mutations (`Game.activeMutations`, a `Set`) are run-only and reset every round — see each mutation's effect wired into `registerCombo()`, `checkSizeTier()`, `updateMutationEffects()`, and `handleHoleCollisions()`. In the final `CONFIG.overdrive.triggerSecondsRemaining` seconds, `checkOverdriveTrigger()` picks a seeded variant (`blackout` dims the world; `portal_rain` spawns a wave of bonus objects) and tags the result screen (`BLACKOUT FINISH` / `PORTAL STORM`).

### Meta: Miasto/Core City hub, Warsztat, bottom nav, Wyzwania (Vector Hole v4 / GDD 4.0)

- The main menu is the **Miasto / Core City hub**: a header (currency + a small ⚙ gear button to Profile) above a hero `.hub-card` whose centerpiece is a living Core City skyline canvas (`drawCityScene()` via `renderHubCity()`: 3 starter buildings + 15 more built one sixth per level, a crane over the one under construction, and new buildings rising when you return after a run), `LVL X` / `%` overlays, a progress bar, the next-reward chips and a 6-stop milestone road (`renderHubLevelDots()`); below that three "jak to działa" icon tiles and a CTA row (`GRAJ 2:00` primary, `WYZWANIE DNIA` secondary → opens the Wyzwania tab). **The single rule that governs this whole area (GDD 4.0 §4/§7/§8, stated in red in the source doc): Campaign missions never fill Core City — only an Arena round or a Daily round does, both exclusively inside `Game.finalizeRun()`.** `endCampaignMission()` (Campaign's own end-of-round path) never calls `finalizeRun()` and never touches `save.hub`.
- **Core City progress is additive per run, not a flat rate** (`CONFIG.hub.coreCity`): an Arena run grants `arenaCompleteGain` (+8%), plus `arenaTop3Gain` (+2%) for a top-3 finish, plus `arenaFirstGain` (+3%) for 1st place, plus `arenaNewPbGain` (+2%) for a new `save.stats.bestArenaScore`. A Daily run grants `dailyFirstClearGain` (+20%) for the day's first clear, plus `dailyNewBestGain` (+10%) for a new Daily best. `save.hub.coreCharge` (0-100) and `save.hub.coreLevel` (starts at 1) are separate fields; overflow past 100% carries into the next level in a `while` loop (so a big gain can grant more than one level at once) instead of resetting to 0. `Game.grantCoreCityLevelReward(level)` looks up `CORE_CITY_LEVEL_REWARDS[level]` (LVL2 Trail „Impuls”, LVL3 Rdzeń „Kryształ”, LVL4 Efekt „Pixel Burst”, LVL5 Overdrive „Fala”, LVL6 Zestaw „Pryzmat” + badge, all + coins) and falls back to `hub.milestoneFallbackCoins/Prisms` for LVL7+ (no authored reward beyond LVL6 — see plan doc).
- **Warsztat** (`shopScreen`) has four equip categories sharing one render/purchase path (`Game.renderCosmeticGrid()`/`cosmeticLockLabel()`): **Rdzeń** (`SKINS`, Coins), **Trail** (`AURAS`, Coins or Prisms — same following-glow render path as v2/v3, renamed in the UI only), **Efekt pochłaniania** (`EAT_EFFECTS`, overrides `triggerEatFeedback()`'s particle/ripple color for eats the player caused), **Overdrive** (`OVERDRIVE_SKINS`, overrides the `--overdrive-color` CSS var on Arena's Overdrive banner — cosmetic only, doesn't change which seeded variant fires). A live "PODGLĄD NA ŻYWO" preview canvas shows the current loadout with the real in-round `Hole.draw()` (plus a fragment being eaten in the selected Efekt color); `updateWarsztatPreview()` only refreshes its text labels. Items with an `unlockSource` (Core City level or a specific mission id) are reward-only — they show their unlock source instead of a price and are never buyable from the grid.
- **Bottom nav** (`#bottomNav`, one persistent bar, not per-screen markup): Miasto/Dzielnice/Warsztat/Wyzwania, rendered by `Game.renderBottomNav(activeScreenId)` on every `showScreen()` call. Unlock order (GDD 4.0 §5.5): Dzielnice is always available; `Game.isArenaUnlocked()` (GRAJ 2:00 / Wyzwanie dnia's underlying round) requires mission `M00` (the tutorial, not `M01` — see below); `Game.isWarsztatUnlocked()` requires `M02` (or already owning a non-default cosmetic); `Game.isWyzwaniaUnlocked()` requires `M04`. Before `M00` clears (`Game.isFirstRun()`), Miasto collapses to a single-CTA welcome card (`#hubWelcome`, ZAGRAJ TUTORIAL) and the bottom nav is hidden entirely; after that, locked tabs show dimmed with a lock badge and tapping one opens an explanation of what the tab is and which mission unlocks it.
- **Info sheet (`#infoSheet`, `Game.openInfoSheet()`)**: one generic "what is this?" popup behind every hub element that looks tappable — currency pills, Core City reward chips, level dots/ring/"wszystkie nagrody" row (→ `openCoreCityRoadmap()`), locked nav tabs (`openLockedTabInfo()`), locked districts (`openLockedDistrictInfo()`). Locked mission rows are selectable (preview + reason GRAJ is off) rather than disabled. Player feedback: nothing on a hub screen should look clickable and silently ignore the tap.
- **Unlock celebrations (`#unlockOverlay`, `Game.queueUnlockCelebrations()`)**: a full-screen "ODBLOKOWANO!" animation (lock shakes and cracks, icon pops with rays and a particle burst, pure CSS keyed by `--unlock-color`) for every `FEATURE_UNLOCKS` entry (GRAJ 2:00, Warsztat, Wyzwania, each new district) and for cosmetic rewards queued at grant time (`queueRewardCelebration()` from `grantCoreCityLevelReward()` and M24's skin). It plays shortly after the mission-result / game-over screen appears; its primary button jumps straight to the new feature. `save.unlocks.announced` makes each feature play exactly once (the v9 migration pre-fills it with whatever an existing save already had); `save.unlocks.fresh` drives the "NOWE" badges on nav tabs, district chips and GRAJ 2:00 until first visited. `FEATURE_GATES` are the pure save→bool gates behind `isArenaUnlocked()`/`isWarsztatUnlocked()`/`isWyzwaniaUnlocked()`.
- **Screen art (`prepCanvas()`, `Game.startScreenAnim()`)**: one RAF loop animates every canvas outside the board while its screen is visible — the Miasto city (or the first-run welcome hole), Dzielnice's 2×2 district tiles (`drawDistrictTile()`: a skyline lighting up per cleared mission with the district's boss landmark in front, colors in `DISTRICT_COLORS`), the Warsztat showroom preview, the Wyzwania map (`drawDailyMapPreview()` of `Game.computeDailyLayout()`, which replays the Daily seed's modifier roll → `createObjects()` → spawn, so it is the real layout) and the evolution card demos. Evolution/power offers share `Game.showPowerCards()`: each card has a looping demo (`drawPowerDemo()`/`POWER_DEMO_FOR`), a plain Polish name, a WHEN `tag` and a `desc` with the real numbers. `.screen-inner` has `overflow-x: hidden` and non-shrinking children — no sideways panning on phones.
- **Arena only shows what Campaign has taught (v7).** Player feedback: Arena shouldn't display objects or the "eat a smaller rival" mechanic before the player has actually learned them in Campaign. `save.campaign.discoveredTypes` (a list of `CampaignEntity`/`TIERS` type names) grows every time `resolveCampaignEntity()` resolves a new type, regardless of whether that mission is ever completed; `save.campaign.discoveredHoleEating` flips true the first time `handleCampaignCollisions()`'s new "player bigger than bot" branch fires (Campaign bots were pure hazards before this — a documented simplification — never prey). `Game.createObjects()` only spawns a `TIERS` group once its key appears in `discoveredTypes` (falling back to everything only if the set is somehow empty, which a real player can't reach). `M00` ("Zanim zaczniesz", `CAMPAIGN_MISSIONS`' first entry, a prologue not part of the GDD's 24 authored missions) exists specifically to front-load one T1/T2/T3 object plus rival-eating before Arena unlocks on it — without it, unlocking Arena straight off `M01` (which only teaches `fragment`) would leave every other tier permanently locked with nothing to grow into, a softlock. `M00` sits first in Plac Neonów's `missions` array (5 entries instead of the usual 4) rather than renumbering `M01`-`M24`. Its `goal.type` is `'tutorialChecklist'` (a list of `{entityType, count}` / `{type:'eatRival', count}` steps, all required) — the one goal shape not keyed by a single entity type/count, handled by its own branches in `checkCampaignGoal()`/`campaignGoalItems()`/`campaignGoalEntityTypes()`.
- **Wyzwania** (`challengesScreen`) hosts both existing daily systems in one place: the rotating daily mission (`MISSIONS`/`missionForDate()`, unchanged since v2) and the Daily Seed Challenge (`startDailyChallenge()`), plus a live UTC countdown to the next reset (`Game.updateChallengeCountdown()`, ticks every second) and a consecutive-day streak (`save.daily.streak`, computed in `finalizeRun()` via `previousDateKey()`).
- **Run Setup** (`runSetupScreen`) offers casual-only consumable tools (`RUN_TOOLS`: Shield, Magnet), Coins-only, consumed at round start (`Game.confirmRunSetup()`).
- **Profile**: an optional display name (never required before the first run), passed through a placeholder blocklist (`moderateName()` — explicitly **not** production moderation, just a non-empty safeguard) plus a stable guest ID.
- **Share**: `Game.shareResult()` uses `navigator.share` (feature-detected via `canShare`) with a clipboard-copy fallback — never assumes Web Share exists.
- **Quick-equip popup (v5, `#quickEquipScreen`)**: opened from the pause sheet's "ZMIEŃ WYGLĄD" button (`Game.openQuickEquip()`) so a player can swap Trail/Efekt pochłaniania/Overdrive mid-run without leaving to the full Warsztat. Each row cycles to the next **owned** item in that category (`Game.cycleQuickEquip(category)`); it reuses the same `pendingLoadout`/`onEquipClick()` commit path the Warsztat tabs already use instead of a second equip code path — "WYBIERZ" calls `onEquipClick()`, "ZAMKNIJ" discards the pending cycling back to `save.*.selected`. Doesn't touch Rdzeń (ring skin) — matches `design/screens/wybor_narzedzia.svg`, which only lists the other three categories.
- **Game over / results (v5, `gameOverScreen`)**: a hero score (with a "NOWY PB" badge when the run beat the previous Arena/Daily best), a size-tier badge from `CONFIG.sizeTiers[].label` (T1–T5, previously tracked only for analytics — see `checkSizeTier()`), a coins-earned card, and a Core City before→after card whose two-tone bar (`resultCoreBarBefore`/`resultCoreBar`) shows the dim pre-run % plus a bright segment for just this run's gain, computed in `endRound()` from a snapshot taken *before* `finalizeRun()` mutates `save.hub.coreCharge`.

### Campaign mode (Vector Hole v3, fully authored in v4, mission-object enrichment in v6)

A second simulation from Arena, switched via `Game.mode` ('arena' | 'campaign') and dispatched in `Game.loop()` to either `update()`/`render()` (Arena) or `updateCampaign()`/`renderCampaign()` (Campaign) — they don't share entity lists (`WorldObject` vs `CampaignEntity`), each with its own class/pool/eating logic, even though Arena's `TIERS` now deliberately mirrors Campaign's `CAMPAIGN_ENTITY_STATS` bestiary (color/size/tier-gate/value) so the two modes present the same objects — see `WorldObject`'s own doc comment above.

- **Entities**: `CampaignEntity` (fragment/prop/vehicle/capsule/marker/node/pylon/landmark/gate), stats and per-type eat-gating in `CAMPAIGN_ENTITY_STATS`. Growth uses its own tier ladder, `CAMPAIGN_TIERS` (T1–T6, independent of Arena's `sizeTiers`) — a tier threshold gates which entity types are eatable, and T4 gates whether a mission's landmark ("big eat") can be reached at all.
- **Missions**: `CAMPAIGN_MISSIONS` — all **24 missions across all 6 districts** (`DISTRICTS`: Plac Neonów, Park Impulsów, Port Syntez, Galeria Glitch, Dachy Prądu, Rdzeń Miasta; 4 missions each, except Plac Neonów's 5 — see `M00` below) per GDD 4.0 §6, up from v3's 8 authored missions in the first 2 districts. Each mission has a `goal` (one of `eatCount`/`comboChain`/`gatesPassed`/`activateAndDevour` — all 24 missions reuse these same four shapes, see plan doc for how each district's flavor text maps onto them), an optional `medal`, a curated `setup` spawned by `Game.buildCampaignMission()`, NELA narration lines, and a first-clear reward. Each district's mission 4 unlocks the next district (`reward.unlockDistrict`) except the campaign's last mission (`M24`), which instead grants a dedicated final cosmetic (`reward.unlockSkin`). `Game.checkCampaignGoal()` / `Game.endCampaignMission()` drive success/fail; there is no failure state beyond running out of time (no elimination). `CAMPAIGN_MISSIONS` also has a 25th entry, `M00`, a prologue tutorial outside the GDD's 24 — see the Arena-discovery-gating bullet above for why it exists and its own `'tutorialChecklist'` goal shape.
- **Object glyphs and landmark silhouettes (v6)**: `CampaignEntity` carries an optional per-mission `glyph` (via `MARKER_GLYPHS`/`PROP_GLYPHS`/`NODE_GLYPHS` plus a one-line check for the two `pylon` missions), so a `node`/`pylon`/`marker`/`prop` reused across several missions with different GDD names (e.g. węzeł/zasilacz/mostek all being `'node'`) gets a distinct look per mission instead of one generic sprite — purely visual, `CampaignEntity.draw()` branches on it but `checkCampaignGoal()`/stats stay keyed by `type`. Landmarks branch on `landmarkId` in `draw()` for 6 unique silhouettes instead of a shared pulsing double-ring.
- **Portal (M13), Mostek (M19), Pas przelotu (M18) — real mechanics (v6)**: the 3 GDD objects whose verb isn't "pochłoń" now have actual behavior instead of a relabeled goal type. `Game.handlePortalTouch()` teleports the player to a fixed far-side anchor; `Game.handleCampaignBridges()` powers a mostek in place without consuming it (`handleCampaignEating()` explicitly skips `glyph === 'mostek'` nodes); `Game.handleCorridorZone()` tracks entry/exit sides so a `gatesPassed` pass only counts if the whole crossing happened while lit. Brama (M05) stayed a plain point-touch gate. See `docs/VECTRE_V6_PLAN.md` §3.3 for the open-question decisions (one-way/single-use portal, no separate "zasilacz" object, etc.).
- **Powers**: `CAMPAIGN_POWERS` (Magnes/Reaktor/Impuls/Skaner) — a separate, smaller pool from Arena's `MUTATIONS`, offered once per mission via `Game.offerCampaignPowers()` (reuses the same evolution overlay DOM/CSS as Arena's evolution cards).
- **Dzielnice**: the bottom nav's Dzielnice tab opens `campaignScreen` (district map + mission list/detail, `Game.renderCampaignMap()`); its header shows the *selected district's own* rebuild fraction ("ODBUDOWA: X% · Y z Z misji", set in `selectCampaignDistrict()`) — **never** the Miasto/Core City percentage, per GDD 4.0 §8.4's explicit anti-confusion rule. Mission end shows `missionResultScreen`, not Arena's `gameOverScreen`.
- Save progress lives in `save.campaign` (`unlockedDistricts`/`completed`/`medals`), independent of Arena's `save.hub`/`save.daily`/`save.mission`.

See `docs/VECTRE_V4_PLAN.md` for the full v4 changelog, `docs/VECTRE_V3_PLAN.md` for the original v3 scope call, and `docs/VECTRE_V6_PLAN.md` for the v6 object/landmark/mechanic enrichment above; known simplifications (bots are passive wanderers, Brama's cycle rhythm is fixed rather than balanced, balance is unverified, a couple of mission descriptions with two intertwined mechanics were mapped onto one tracked goal, M16's "lustro" glyph has no real mirror/reflection effect behind it) are documented across the v4 plan doc §2.1 and the v6 plan doc §6.

### What's deliberately not built

No backend of any kind (daily/global leaderboards, cloud save, accounts are all local-only). No real ad/IAP SDK — `showInterstitialAd()`/`watchRewardedAd()` are still a timed fake progress bar. No full authored chunk/district generator (`CONFIG.flags.proceduralDistricts` stays `false`) — only a single seed-driven "Rush Hour" run modifier exists as a lightweight stand-in. No audio system. No Core City "season/prestige loop" past LVL6 (GDD 4.0 §8.2 calls this out as a later phase). Check `docs/VECTRE_V4_PLAN.md` before assuming any of these exist or extending them further.
